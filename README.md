# 미국주식 모의매매 봇

Python 3.10 이상에서 압축을 풀고 해당 폴더에서 실행합니다. 외부 패키지와 API 키 없이 실행됩니다.

```powershell
python demo.py
```

- `bot.py`에는 종목 스캐너, 시장·위험 거부권, 소셜 검토 인터페이스, 모의 체결이 들어 있습니다.
- `demo.py`는 합성 시세로 돌파만, 시장 거부권 추가, 소셜 검토 추가를 나란히 실행합니다. 신규 매수 보류, 매수·청산, 손익·최대 낙폭을 출력합니다.
- 예제 임계값은 거래량 3배, 15분 가격 범위 0.5%, 15분 거래대금 약 100만 달러, 최대 스프레드 0.3%, 일일 손실 한도 1%입니다. 모두 초기 검증값입니다.
- 시장 상태와 상대 거래량은 입력으로 주어집니다. 실제 데이터 연결 시 거래일별 정규장 분봉·호가, 시간대별 과거 거래량, 시장 지표를 공급해야 합니다.
- 소셜 검토 입력이 없으면 로그를 남깁니다. 예제에서는 합성 루머가 발견된 경우에 매수를 막습니다.
- 예제 손익은 가상의 가격과 비용을 사용한 동작 점검 결과입니다. 실제 시세·증권사·X·Reddit·AI API는 연결되지 않았습니다. 공개 장초반 돌파 전략은 별도 비교 구현이 필요합니다.

## 매수 압력에도 가격이 제자리인 경우

`python pressure.py`로 가상 체결 집계 예제를 실행합니다. 같은 시간대의 평소 분류 가능 거래대금 대비 3배 이상, 매수 주도 체결대금 비중 70% 이상, 매수·매도 중간 호가의 고저 범위 0.5% 이하를 초기 관찰 조건으로 둡니다. 거래 주체의 신원을 추정하거나 매수 주문을 내는 기능은 없습니다. 체결 방향을 제공하는 피드 또는 시각이 맞춰진 체결·호가로 만든 집계가 필요합니다. 이 감지기는 기본 돌파 데모와 별도로 실행됩니다.

## Windows에서 대시보드 열기

1. ZIP 전체를 한 폴더에 압축 해제합니다.
2. `open-dashboard.bat`를 더블클릭합니다. Python 3.10 이상이 필요합니다.
3. 실행할 때마다 `dashboard.py`가 `demo.py`와 `bot.py`를 실행하고 결과를 `trading-dashboard.html`에 넣어 브라우저로 엽니다.

PowerShell에서는 압축을 푼 폴더에서 `python dashboard.py`를 실행해도 됩니다. 저장한 X·Reddit 글은 예시입니다.

`위원회 + 매수 압력` 전략은 가상 체결 집계로 매수 압력 조건을 확인한 뒤 돌파를 기다립니다. 기존 `분석위원회`와 비교할 수 있습니다. 실제 체결 데이터는 연결 전입니다.

## 공개 과거 데이터 시험

LOBSTER의 AAPL 2012-06-21 NASDAQ 레벨 1 샘플에서 메시지와 호가 CSV를 받아 각각 `message.csv`, `orderbook.csv`로 저장하고, 두 파일을 담은 폴더를 지정합니다.

```powershell
python historical.py "C:\path\to\sample"
```

이 시험은 한 거래일뿐이므로 같은 시각의 여러 거래일 평균 대신, 당일 현재 구간과 겹치지 않는 앞선 15분 구간들의 중앙값을 임시 기준으로 사용합니다. 시장·소셜 거부권은 두 전략 모두 적용하지 않습니다. 결과는 체결·호가 입력을 처리하는 점검이며, 전략 평가에는 여러 거래일과 종목이 필요합니다.

샘플 출처 https://data.lobsterdata.com/info/DataSamples.php
샘플 미러 https://huggingface.co/datasets/y7pan/lobster-data

## 여러 거래일 시험

데이터를 `데이터폴더/YYYY-MM-DD/종목/message.csv`와 같은 위치의 `orderbook.csv`로 배치합니다. 두 CSV는 동일한 LOBSTER 레벨 1 기록이어야 합니다.

```powershell
python historical.py "C:\path\to\data"
```

종목별로 이전 거래일의 같은 15분 구간 중앙값을 사용합니다. 첫날은 기준을 쌓습니다. 하루치만 있으면 `--intraday-reference`를 붙여 당일 기준으로 입력 경로를 점검할 수 있습니다. 입력 날짜가 미국 표준시라면 `--utc-offset=-5`를 지정하세요. 이 버전은 한 실행에서 고정 UTC 오프셋을 사용합니다.

공개 샘플 점검(2012-06-21, AAPL·AMZN·GOOG·INTC·MSFT)에서 당일 기준으로 1,520개 구간을 평가했습니다. 상대 거래량 조건 69개, 매수 압력 조건 0개, 양쪽 체결 0건입니다. 같은 시간대 기준 실행에서는 이전 거래일이 없어 평가 구간이 0개였습니다. 기존 대시보드는 가상 시세 리플레이를 표시합니다.

## 과거 결과를 브라우저에서 보기

`historical-dashboard.html`에는 공개 5종목 하루치 샘플을 실행한 결과가 들어 있습니다. 새 데이터를 넣으면 아래 명령으로 대시보드를 다시 생성합니다.


한 날짜만 있고 당일 비교로 입력을 점검하려면 `--intraday-reference`를 추가합니다. 기본 실행 파일은 기존 가상 시세 대시보드를 엽니다.

#### 대량 매수인데 가격이 제자리인 구간 이후 (`absorption.py`)

15분 구간별로 매수 주도 체결대금 비율을 나누고, 그중 체결대금이 평소 3배 이상이면서 중간 호가 범위 0.5% 이하인 구간(대량·정체)의 15·30·60분 뒤 중간 호가 변화를 봤습니다. 매매 비용은 빠진 값입니다. "사건"은 같은 종목에서 15분 넘게 떨어진 구간을 따로 센 수입니다.

매수가 약간 우세(50~70%)한데 대량 체결에도 가격이 멈춘 구간 뒤에는 평균적으로 올랐고, 매수가 압도적인(70% 이상) 구간은 오히려 아니었습니다. 기존 매수 압력 조건(70% 이상)이 거의 안 걸리고 성과도 없던 이유와 맞습니다. 다만 구간이 매분 겹쳐 t값이 부풀려지고, 이 구간 경계를 결과를 보고 고르면 과거에 끼워 맞추게 됩니다.

#### 며칠 보유 방식 (지수, 결과를 보기 전 2026-11-16 기록)

종목별 일별 주가는 무료·계정 없이 공식적으로 받을 곳을 아직 못 찾았습니다(Stooq는 자동 다운로드에 브라우저 확인을 요구해 쓰지 않음). 그래서 먼저 FRED(미국 세인트루이스 연준)의 나스닥 종합지수 일별 종가(1971~)로 시험합니다. 실제 매매는 지수를 따라가는 ETF(QQQ 등)로 한다고 가정합니다.

- 비용: 매수·매도 각 0.25% + 미끄러짐 0.02%, 매도 시 SEC 수수료. 현금 보유 중 이자는 0으로 둡니다(보수적).
- 체결: 신호가 난 날 종가를 보고 **다음 거래일 종가**에 사고팝니다(신호를 보고 나서 주문하는 시간을 둠).
- 기간: 1990~2009(설계용)과 2010~2026-11(확인용)을 따로 계산합니다. 두 기간 모두 좋아야 의미가 있습니다.

전략(숫자는 널리 쓰이는 기본값 그대로, 결과에 맞춰 바꾸지 않음):

1. 그냥 사서 보유(비교 기준).
2. 추세 추종: 종가가 200일 평균 위면 보유, 아래면 현금.
3. 상승장 눌림 매수: 종가가 200일 평균 위이면서 최근 5일 중 가장 낮으면 매수, 종가가 5일 평균 위로 올라오거나 5거래일이 지나면 매도.

#### 월간 모멘텀 낙폭 방어 (결과를 보기 전 2026-11-17 기록)

월간 모멘텀(위 3번)에 널리 쓰이는 방어 장치를 붙여 같은 데이터·비용·기간으로 비교합니다. 모든 판단은 매달 첫 거래일 종가에 한 번만 하고 다음 날 시가에 체결합니다(매매 횟수를 늘리지 않기 위해).

- A. **시장 추세 필터**: SPY 종가가 200일 평균 아래면 전부 팔고 그 달은 현금, 위면 평소대로 상위 10종목.
- B. **종목 추세 필터**: 12-1개월 수익률이 플러스이고 종가가 자기 200일 평균 위인 종목만 삽니다. 10개가 안 되면 남는 자리는 현금.
- C. A와 B를 함께.

판정: 두 기간 모두 연평균 수익률이 "100종목 같은 비중"보다 높고, 최대 낙폭이 그 비교 기준(-60.9%, -40.1%)보다 작을 것. 생존 편향은 그대로 남아 있으므로 통과해도 모의 운용 후보일 뿐입니다.

- 실행: `run-paper-momentum.bat` 더블클릭 또는 `python paper_momentum.py`(한 달에 한 번 이상, 매달 첫째 주 권장). 최신 일별 데이터를 받아 처음부터 다시 계산하고 `paper/momentum.md`(현재 보유·성과·다음 주문)와 `paper/momentum.json`을 갱신합니다. 매번 커밋해 기록이 나중에 바뀌지 않았음을 git 이력으로 남깁니다.
- 비교: 같은 날 시작한 SPY 보유, 100종목 같은 비중 보유.
- 판정 시점: **12개월 뒤(2027-11)**. 그 전에는 결과가 좋아도 실제 돈을 넣지 않습니다. 중간에 규칙을 바꾸지 않습니다. 과거 시험상 -30% 이상 하락하는 해가 흔했으므로 큰 하락이 나와도 규칙 위반이 아닙니다.

2. **종목 악재**: 직전 30분에 그 회사를 언급한 기사가 2건 이상이고 평균 논조 -2 이하이면, 이후 30·60분 그 종목 변화가 평소보다 낮다(긍정 +2 이상은 대조군).
3. **급락 앞 뉴스**: 15분 하락폭이 그 기간 종목 15분 변화의 하위 1%인 급락 구간 직전 60분에 회사 뉴스가 있었던 비율이, 아무 구간 직전 60분의 비율보다 높다.

어느 것도 확인되지 않으면 뉴스 신호는 매매에 넣지 않습니다. 확인되면 매수 보류(거부권)로만 쓰고, X 유료 조회는 그때 다시 사용자에게 묻습니다.

전일 종가 대신 당일 첫 체결가를 하락 기준으로 쓴 것은 공개 샘플 날짜가 연속되지 않아 전일 종가가 없기 때문입니다. 거래 대상이 10종목뿐이라 하락 비율은 거친 값입니다. 모든 값은 그 분까지의 체결만 사용합니다. 결과의 `market_avoided_loss`·`market_missed_profit`는 돌파 전략이 체결했지만 시장 거부권 전략은 막은 거래의 손실·이익 합, `weak_market_minutes`는 약세로 판정된 분 수입니다. 거부권으로 매수를 건너뛰면 이후 현금·손실 한도가 달라지므로 두 전략의 순손익 차이와 정확히 같지는 않습니다.

### 비교 후보: 개장 범위 돌파(ORB)

`orb.py`의 매수 전용 ORB를 같은 과거 시험에 함께 돌립니다(`개장 범위 돌파(ORB)`, 지수 데이터가 있으면 `ORB + 시장 거부권`도).

- 개장 범위: 09:30~09:35 다섯 개 분봉의 고가·저가와 거래량
- 후보: 개장 5분 거래량 ÷ 그 종목의 이전 거래일 개장 5분 거래량 중앙값(상대 거래량)이 1배 이상이고, 5분째 종가가 첫 체결가보다 높은(양봉) 종목 중 상위 3개. 종목별 첫 거래일은 기준만 쌓습니다.
- 진입·청산: 이후 처음으로 개장 범위 고가 위에서 마감한 분봉이 신호이고, 고가를 기준선으로 기존 돌파 전략과 같은 규칙(다음 분봉 확인 후 매도호가 체결, 기준선 아래 마감 또는 30분 보유 시 청산)을 씁니다. 종목당 하루 한 번입니다.

공개 연구의 ORB는 보통 개장 범위 저가 손절과 장 마감 청산을 쓰지만, 여기서는 진입 방식만 비교하려고 청산 규칙을 기존 전략과 맞췄습니다. 결과의 `orb_selections`는 날짜별 후보와 상대 거래량입니다. 합성 데이터(둘째 날 B 종목 개장 거래량 10배, 양봉 후 범위 돌파)에서 그날 B만 선택되어 09:42 매수, 30분 뒤 청산됨을 확인했습니다. 실제 데이터로는 아직 실행하지 않았습니다.

## 나스닥 ITCH 원본에서 종목 추출

공식 샘플 https://emi.nasdaq.com/ITCH/Nasdaq%20ITCH/ 에서 받은 ITCH 5.0 gzip 파일을 지정합니다. 날짜별로 반복하고 같은 출력 폴더를 사용합니다. 완성된 날짜 폴더가 이미 있으면 덮어쓰지 않습니다.

```powershell
python itch_extract.py "C:\data\12302019.NASDAQ_ITCH50.gz" "C:\data\sessions" 2019-12-30 AAPL AMZN GOOG INTC MSFT
python dashboard.py --historical "C:\data\sessions" --utc-offset=-5
```

추출기는 주문 추가·취소·체결·교체를 따라 나스닥의 최우선 매수·매도 호가를 재구성합니다. 표시 주문 체결은 반대편을 주도 방향으로 집계합니다. 방향 미상의 비표시 체결은 전체 거래량에 들어가며 매수·매도 주도 비중 계산에서는 빠집니다. 경매와 사후 체결 취소는 이 버전에서 반영하지 않습니다. 장 마감 이벤트 전에 끝난 입력은 완료된 날짜로 저장하지 않습니다.
